# Phase 1 검증 기록

## 분석 진행률 개선 로컬 검증 (2026-09-17)

- Backend 15개 테스트 통과: 보고된 진행률 고정, 상태 재조회, 사용자 분리, 완료 시간 저장, 서버 재시작 후 완료 복원과 중단된 작업의 재시도 안내를 포함합니다.
- Playwright 7개 통과: 기존 녹음·업로드·실제 Basic Pitch·편집·재생·확정·저장에 더해 진행률 임의 증가 방지, 새로고침 및 화면 복귀, 실패 재시도, 100% 이후 편집기 이동을 확인했습니다.
- `scripts/smoke_progress.py`: 실제 모델의 7개 오디오 구간 완료에 따라 31→37→44→50→57→63→70%를 보고했습니다. 8개 음표의 pitch/start/end/velocity가 기존 Spotify `predict()` 경로와 모두 일치했습니다.
- TypeScript 검사 및 Vercel 환경변수를 적용한 프로덕션 빌드 통과. 모바일 390px/320px 화면과 가로 넘침을 확인했습니다.

## 실제 무료 HTTPS 배포 검증 (2026-09-17)

- 공개 프론트엔드: https://hum-phase1.vercel.app (Vercel Hobby).
- 백엔드: https://hum-phase1-api.onrender.com (Render Free). 실제 Linux amd64 Docker 빌드와 배포가 완료되었습니다.
- 배포 소스 `77fcfdb`: 공개 주소 HTTP 200, HTTPS, 마이크 Permissions-Policy, 정확한 production origin의 CORS preflight를 확인했습니다.
- 외부 API 통합 검증: 합성 10초 WAV 업로드, 실제 Basic Pitch 8음 인식, 음정 수정, 원본 음표 불변, 원본 오디오 SHA-256 일치, Melody Lock, 저장, 다시 읽기, MIDI 헤더, 다른 브라우저 식별자로 접근 시 404를 확인했습니다.
- 실제 공개 웹사이트의 모바일 크기 Chromium에서 파일 업로드 → Basic Pitch → 피아노롤 표시가 통과했습니다. 10초 음원 분석에 약 258초가 걸렸으며 localhost API 호출이나 브라우저 실행 오류는 없었습니다.
- 같은 공개 HTTPS 주소에서 Playwright 5개 테스트가 모두 통과했습니다(전체 약 1.6분): 모바일 파일 업로드·터치 음정 수정·길이 조절·실행 취소·임시 저장 복원, 가상 마이크 10초 WebM 녹음·실제 분석·신스 오디오 신호 검출·Melody Lock·저장·새 탭 복원, 짧은 녹음, 마이크 권한 거부, 서버 연결 실패 안내.
- 첫 실행은 로컬 기준 150초 대기시간 초과로 중단했습니다. 앱 코드는 바꾸지 않고 자동 테스트에 `HUM_TEST_ANALYSIS_TIMEOUT_MS=600000`을 적용해 다시 검증했습니다. 서버가 준비된 뒤 녹음부터 저장까지의 테스트는 약 29초에 통과했습니다. 첫 분석과 후속 분석 속도는 다릅니다.
- 데스크톱 및 390px/320px 모바일 스크린샷에서 화면과 음표를 확인했고 페이지 가로 넘침이 없었습니다. Backend 13개 테스트와 TypeScript 검사도 다시 통과했으며 기존 localhost:3000의 HTTP 200을 확인했습니다.
- 서버 절전 후 재접속 시 health 응답을 확인했습니다. 무료 임시 저장소는 작품 보관용이 아니며 재시작·절전·재배포 시 데이터가 사라집니다.
- 실제 아이폰 하드웨어 마이크와 실제 사람의 노래 인식 품질 검증은 별도로 필요합니다. 아래는 외부 배포 이전의 준비 및 로컬 검증 기록입니다.

## 무료 배포 준비 검증 (2026-09-16)

- Backend 13개 테스트 통과: 기존 보존 규칙에 더해 CORS preflight, 브라우저별 데이터 분리, 비동기 분석과 실패 재시도를 확인했습니다.
- 기존 localhost 브라우저 테스트 5개와, 별도 origin의 프론트/백엔드를 직접 연결한 브라우저 테스트 5개가 통과했습니다. 후자는 실제 CORS와 비동기 상태 조회를 사용합니다.
- Vercel 환경변수 조건을 적용한 프로덕션 빌드와 TypeScript 검사가 통과했습니다. 빌드 검증에는 예시 HTTPS origin을 사용했으며 실제 외부 배포는 아닙니다.
- Linux ARM64 Docker 이미지에서 실제 Basic Pitch 분석 성공. 512MB RAM 제한에서도 10초 테스트 음원의 8개 음을 인식했습니다. 이는 Render의 실제 CPU·네트워크 성능 검증을 대신하지 않습니다.
- Linux amd64 추가 이미지 빌드는 로컬 디스크 공간 부족으로 중단했습니다. 해당 아키텍처의 최종 빌드와 HTTPS 실환경 검증은 Render 연결 후 필요합니다.
- 배포 설정은 Vercel Hobby + Render Free이며 영구 디스크/유료 리소스는 포함하지 않습니다. 무료 서버의 녹음·프로젝트는 절전·재시작·재배포 시 사라질 수 있습니다.
- Vercel/Render 계정 연결이 없어 아직 외부 배포 완료나 HTTPS 주소 발급을 확인하지 않았습니다. 아래 내용은 최초 로컬 MVP 검증 기록입니다.

검증일: 2026-09-15. 환경: macOS Apple Silicon, Node 22.22.0, Python 3.9.6.

## 통과한 항목

- Backend 단위/통합 테스트 9개: 원본 보존, 음정·길이 수정, 확정·저장, 새 앱 인스턴스에서 복원, 동시 수정 충돌, 잘못된/빈/짧은 오디오, 경로 입력 검증, 미허용 origin, 분석 실패, MIDI 실패 시 확정 방지.
- 실제 Basic Pitch ONNX 추론: 합성 10초 WAV의 8음 `C4 D4 E4 G4 E4 D4 C4 E4`를 예상 pitch로 모두 검출. MIDI 헤더 및 생성 확인.
- Playwright 브라우저 테스트 5개: 가상 마이크 MediaRecorder 10초 녹음과 WebM 업로드, 실제 분석, 드래그로 음정 수정, 길이 입력, 실제 신스 오디오 신호 검출, Melody Lock, 저장, 새 탭 복원, 가사 입력, 마이크 거부, 서버 실패, 모바일 터치 이벤트, 길이 드래그, 실행 취소, 임시 저장 복원, 너무 짧은 녹음.
- 데스크톱 1280/1440px와 모바일 390/320px 화면 확인. 가로 페이지 넘침 없음. 피아노롤 내부는 의도적으로 스크롤 가능.
- `pip check`: 의존성 충돌 없음.
- `npm run build`: Next.js 16.3.5 Webpack 프로덕션 빌드와 TypeScript 검사 통과.
- `.env`, 녹음 파일, 프로젝트 JSON, 모델 실행 데이터, 가상환경, node_modules, 빌드·테스트 산출물 Git 제외 확인.

스크린샷은 `/tmp/hum-screens/`에 있습니다. 사용자 녹음을 저장소에 넣지 않기 위해 테스트 캡처와 테스트 프로젝트는 Git에 포함하지 않습니다.

## 구분해서 볼 결과

모델에 직접 전달한 WAV는 8음을 정확히 검출했습니다. 같은 테스트 음원을 가상 마이크 → 브라우저 압축 녹음으로 전달한 경우에는 추가적인 짧은 음표가 검출되기도 했습니다. 따라서 합성 WAV 성공을 실제 노래의 정확도 보장으로 해석하면 안 됩니다.

이 환경에서 실제 사람 목소리나 물리 마이크를 대신 테스트하지 않았습니다. 사용자 본인이 약 10초 흥얼거려 보는 확인이 남아 있습니다. 실제 iOS/Safari 녹음도 별도 확인이 필요합니다.

## 빌드 도구

Turbopack의 프로덕션 빌드에서 보조 프로세스의 포트 바인딩 권한 오류가 발생했습니다. `npm run build`는 Next.js 공식 `--webpack` 옵션을 사용하도록 변경했습니다. 로컬 개발 서버의 Turbopack 동작과 브라우저 테스트는 정상입니다.

## 범위

STT는 공급자 인터페이스와 수동 입력만 구현했습니다. AI 편곡, AI 보컬, 믹싱/마스터링, 배포, 결제 등 Phase 2 기능을 추가하지 않았습니다.
