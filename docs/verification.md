# Phase 1 검증 기록

검증일: 2026-09-15. 환경: macOS Apple Silicon, Node 22.22.0, Python 3.9.6.

## 통과한 항목

- Backend 단위/통합 테스트 9개: 원본 보존, 음정·길이 수정, 확정·저장, 새 앱 인스턴스에서 복원, 동시 수정 충돌, 잘못된/빈/짧은 오디오, 경로 입력 검증, 미허용 origin, 분석 실패, MIDI 실패 시 확정 방지.
- 실제 Basic Pitch ONNX 추론: 합성 10초 WAV의 8음 `C4 D4 E4 G4 E4 D4 C4 E4`를 예상 pitch로 모두 검출. MIDI 헤더 및 생성 확인.
- Playwright 브라우저 테스트 5개: 가상 마이크 MediaRecorder 10초 녹음과 WebM 업로드, 실제 분석, 드래그로 음정 수정, 길이 입력, 실제 신스 오디오 신호 검출, Melody Lock, 저장, 새 탭 복원, 가사 입력, 마이크 거부, 서버 실패, 모바일 터치 이벤트, 길이 드래그, 실행 취소, 임시 저장 복원, 너무 짧은 녹음.
- 데스크톱 1280/1440px와 모바일 390/320px 화면 확인. 가로 페이지 넘침 없음. 피아노롤 내부는 의도적으로 스크롤 가능.
- `pip check`: 의존성 충돌 없음.
- `npm run build`: Next.js 16.3.5 Webpack 프로덕션 빌드와 TypeScript 검사 통과.
- `.env`, 녹음 파일, 프로젝트 JSON, 모델 실행 데이터, 가상환경, node_modules, 빌드·테스트 산출물 Git 제외 확인.

스크린샷은 `/tmp/hum-screens/`에 있습니다. 사용자 녹음을 저장소에 넣지 않기 위해 테스트 캡처와 테스트 프로젝트는 Git에 포함하지 않습니다.

## 구분해서 볼 결과

모델에 직접 전달한 WAV는 8음을 정확히 검출했습니다. 같은 테스트 음원을 가상 마이크 → 브라우저 압축 녹음으로 전달한 경우에는 추가적인 짧은 음표가 검출되기도 했습니다. 따라서 합성 WAV 성공을 실제 노래의 정확도 보장으로 해석하면 안 됩니다.

이 환경에서 실제 사람 목소리나 물리 마이크를 대신 테스트하지 않았습니다. 사용자 본인이 약 10초 흥얼거려 보는 확인이 남아 있습니다. 실제 iOS/Safari 녹음도 별도 확인이 필요합니다.

## 빌드 도구

Turbopack의 프로덕션 빌드에서 보조 프로세스의 포트 바인딩 권한 오류가 발생했습니다. `npm run build`는 Next.js 공식 `--webpack` 옵션을 사용하도록 변경했습니다. 로컬 개발 서버의 Turbopack 동작과 브라우저 테스트는 정상입니다.

## 범위

STT는 공급자 인터페이스와 수동 입력만 구현했습니다. AI 편곡, AI 보컬, 믹싱/마스터링, 배포, 결제 등 Phase 2 기능을 추가하지 않았습니다.
