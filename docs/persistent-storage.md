# 영구 저장 전환 준비

2026-10-15 기준: 백업·복원 도구와 로컬 복원 검증 완료. 운영 저장소 전환은 아직 수행하지 않았습니다.

## 현재 구조와 선택 사항

프로젝트 JSON, 원본 오디오, 분석용 WAV, 원본·수정 음표와 MIDI는 `HUM_DATA_DIR` 아래에 저장됩니다. 브라우저별 공간은 `clients/<식별자 해시>/` 아래에 있으므로 **데이터 루트 전체**를 이전해야 합니다. 브라우저의 접근 식별자는 별개이며, 브라우저 데이터를 삭제하면 기존 공간에 접근할 수 없습니다.

- 기존 파일 구조를 유지하는 경로: Render 유료 서비스에 영구 디스크를 연결하고 `/data`에 마운트, `HUM_DATA_DIR=/data/projects`, 인스턴스 1개 유지.
- 무료 서버를 유지하는 경로: 외부 영구 저장소 선택과 연동이 필요합니다. 현재 repository의 파일 검색, 파일 잠금, 분석기의 로컬 경로 사용까지 변경해야 하므로 버킷 주소만 바꾸는 것으로는 완료되지 않습니다.

Render 영구 디스크는 유료 서비스에 연결하며 마운트 경로 아래 데이터만 재시작·재배포 후 유지됩니다. 디스크 추가 시 재배포가 발생하므로 기존 임시 파일을 먼저 확보해야 합니다. [Render 공식 문서](https://render.com/docs/disks).

기존 `render.yaml`은 무료 설정을 유지합니다. 저장 방식과 비용 범위가 결정되기 전에는 운영 플랜 변경이나 디스크 생성을 실행하지 않습니다.

## 백업과 복원

이 도구는 **서버 파일시스템에 접근 가능한 환경**에서 사용합니다. 공개 HTTP API에서 전체 서버 데이터를 내려받는 기능은 아닙니다. Render Free 환경의 파일 접근·반출 방법은 실제 계정에서 먼저 확인해야 하며, 반출하기 전에 서비스를 재시작하지 않습니다.

모든 백엔드 인스턴스와 분석 작업을 종료한 뒤 backend 폴더에서 실행합니다. `--server-stopped`는 사용자가 정지 상태를 확인했다는 표시이며 도구가 프로세스를 종료하지 않습니다.

```bash
# 로컬 데이터 전체를 저장소 밖의 새 폴더에 백업
.venv/bin/python -m scripts.backup backup ./projects /별도보관위치/hum-backup-20261015 --server-stopped

# 기존 경로에 덮어쓰지 않고 새 데이터 폴더에 복원
.venv/bin/python -m scripts.backup restore /별도보관위치/hum-backup-20261015 /새저장위치/projects --server-stopped

# 복원 경로로 서버 실행
HUM_DATA_DIR=/새저장위치/projects .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

백업은 `data/`와 파일별 SHA-256을 담은 `manifest.json`으로 구성됩니다. `.lock`은 제외합니다. 파일 누락·추가·변경 또는 심볼릭 링크가 발견되면 복원을 중단하며, 기존 대상 폴더는 덮어쓰지 않습니다. 원본 파일을 삭제하거나 수정하지 않습니다. 백업에는 음성과 가사가 포함되며 암호화 기능은 없으므로 접근을 제한한 저장소에 보관하세요. 체크섬은 손상 확인용이며 백업 작성자의 신원을 보증하지 않습니다.

## 전환 완료 판단

1. 원본 데이터 백업과 별도 경로 복원 성공.
2. 같은 브라우저로 프로젝트 수, 제목, 수정 음표, 가사, 확정 상태, 원본 재생, MIDI 확인.
3. 운영 저장 경로와 실제 영구 볼륨 마운트 확인.
4. 서버 재시작 및 재배포 후 동일 데이터 확인.
5. 다른 브라우저의 접근 분리 확인.

현재는 합성 테스트 데이터의 백업·복원 및 새 앱 인스턴스에서 조회까지 검증했습니다. 실제 운영 데이터 이전, 클라우드 재배포 후 보존, 실제 사람 목소리·아이폰 검증은 아직 완료하지 않았습니다.
